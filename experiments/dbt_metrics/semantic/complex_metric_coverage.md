# Complex metric coverage

Run `python3 experiments/dbt_metrics/scripts/run_complex_metrics.py` at the repository root. The checks use generated inputs, disposable PostgreSQL databases, the production Go functions and local dbt. A pass establishes agreement for the tested inputs. The reader table below identifies which runtime paths use SQL shared with a dbt model.

Use the [field catalog](catalog.md) for the unit, field name, producer, dependencies and consumers of each member of a family. The [machine-readable catalog](../models/health_metric_catalog.yml) also covers individual observations and dormant target definitions. The table below records which calculations have an executable comparison. A capture is the set of inputs visible at a fixed decision time. An archived response is evidence of what was displayed.

## Locally connected calculations

| Runtime entry | Calculation exercised by both paths |
|---|---|
| Hourly cache and daily HRV | The aggregate writers share the dbt hour projections. Fresh data and historical HRV give equal weight to source means. The local partial-feed adapter merges exact timestamp/source keys into retained points. Step fixtures distinguish omission, a late minute in an existing hour, confirmed physical withdrawal, complete withdrawal and return. The daily writer and dbt share candidates and prior-value handling for all 14 fields. |
| Dated briefing | One query computes card trends and the weekly sleep summary. The comparison checks the assembled briefing for every synthetic capture in English, Russian and Serbian. |
| PersonalBaselineContext | Channel adapters select the input records. Shared SQL calculates the median, MAD-based spread, count, age and calibration state. |
| WorkoutStats and ListWorkoutTypes | Both storage methods execute the model's aggregate with tenant-scoped inputs. Fixtures include a filtered period, its exact endpoints and a period with no sessions. |
| Oxygen evidence for illness assessment | A shared source-level query computes device counts, threshold counts, minimum and the reading-weighted daily mean. Late corrections and final removal go through the real storage reader. |
| Energy and Readiness | Runtime SQL shares the Energy state transition, personalized band calibration, HRV contribution and composite score with dbt. Go supplies date-aligned inputs and persists scored history. |

The stress writer and dbt also share the sustained/acute load, recovery debt, illness signature and rebound rules. The workout intake and dbt share the per-sample time-in-zone calculation.

The unified-schema check reads each declared dbt binding from its own PostgreSQL fixture and verifies the column type. A metric with only a Go reader sample still has its Go calculation owner. Running the shared SQL inside the backend does not install a dbt relation in a tenant schema.

## Main-night comparison by reader

Run `bash experiments/dbt_metrics/scripts/run_sleep_reference.sh --docker` for the focused check. The aggregate runner includes it as a separate group.

| Reader | Source and evidence |
|---|---|
| Today | The React card reads `sleep_duration_comparison` from `/api/health-briefing`. The handler calls `GetSleepDurationComparison` for the tenant-local wake date. |
| Sleep history | Selecting a date on Sleep calls `/api/sleep/comparison?date=YYYY-MM-DD`. The HTTP test compares the entire fact from both routes on the same date before and after correction, and requests yesterday to check its own window. |
| Local duration research | dbt builds its reference view from the same SQL macro that tenant migration installs. The narrow comparison model reads it via `ref`. The driver compares PostgreSQL’s parsed view definitions on identical inputs, then checks the runtime reader and dbt minute outputs against explicit expectations. The optional duration chart reads exported storage facts from a JSON snapshot. |
| Sent morning report | The delivery integration test sends to a local HTTP stub and reads back the exact sent body, both prepared formats and the archived sleep context. A historical correction changes the fresh comparison from −51 to −42 minutes. The archived text and context retain −51. |

The shared SQL defines the mean over the previous 30 calendar days, excluding the selected wake date. It requires seven complete, plausible, final and eligible nights from the same source, source epoch and algorithm version. The dated storage reader and both dbt comparison projections execute the same PostgreSQL fragment for eligibility, independently rounded durations and signed difference. The focused suite checks six versus seven nights, the two directions of independent rounding, a half-minute tie and a corrected historical input. The test suite retains the previous Go calculation as an independent oracle. Go adds source diagnostics and the fact-version hash to the SQL result.
