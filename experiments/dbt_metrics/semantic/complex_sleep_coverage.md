# Sleep calculations compared with Go

From the repository root, run `python3 experiments/dbt_metrics/scripts/run_complex_sleep.py` with Go, Docker and the pilot's `.venv/bin/dbt` installed. The runner creates a PostgreSQL 16 container bound to loopback, loads generated fixtures, builds the dbt views, runs the Go comparisons, then removes its container. It requires no account data. All counts below describe that fixture.

| Calculation and product reader | Comparison and result |
| --- | --- |
| Main-night duration, prior-night count and personal baseline in Sleep and morning evidence | Over 90 dates, 85 had an exact night, 79 had comparable counts and 72 had numeric reference pairs. The counts, presence, statuses and rounded minute differences matched. Maximum absolute reference difference was zero hours. On five missing dates the morning reader could use an earlier night. The dated view correctly returned no exact night. |
| Stage totals, continuity and quality in the night card | SQL edge fixtures exercise stage coverage and continuity. The Go quality calculation was compared on 90 card rows (one score) and 11 boundary cases (five scores). Score presence and values matched. Cases include a goal change, the spring clock change, a noon boundary, corrections and removal, plus independent profiles. The API and MCP read saved snapshots. ## Boundaries

Equal-ranked devices with equal recorded hours use the ascending UTF-8 source label. Both wake and SRI apply this fallback after their own existing source ranks. The SRI comparison checks that the automatic tied result matches the winning device alone and differs from the rival device alone. Selecting the rival explicitly returns its score. An unobserved preference falls back to the automatically selected device. Historical wake rows retain their recorded formula version until recalculated.

Earlier decisions need the quiet clock and evidence available at decision time. A recomputed current row cannot establish when the original decision was made. The balance comparison starts from accepted episodes and the selected goal history. It does not rebuild missing historical commitments or the saved snapshot archive. In separate storage integration cases, daily wake and onset, the diagnostic probe and sleep architecture honor the same exact label and return a read error if the setting is unavailable. When the preferred device records enough sleep for only one of two consecutive nights, daily wake uses the preference for that night and the automatic result for the other. The historical typical-wake fallback remains outside this comparison. Sleep regularity and briefing sleep efficiency use the briefing comparison runner.
