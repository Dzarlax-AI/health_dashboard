Задача и результат

Грубый gate «сон стабилен» заменён единым объяснимым детектором пробуждения. Вычисленное значение сохраняется как каноническая внутренняя метрика wake_time, используется обоими утренними trigger-путями, доступно через tenant-scoped API и может подтверждаться в Telegram. Подробный экран сна остаётся отдельной задачей.

Ретроспективная проверка решения

Read-only probe прогнан на 68 будних днях с персональным reference 08:00. Первоначальный midnight-summary вариант был отвергнут.

Фактический алгоритм wake-v1

  1. В tenant timezone загрузить raw sleep rows ночи и выбрать один источник существующим правилом Apple Watch → RingConn → max coverage.
  2. Основной сигнал: максимальный конец start + qty подробной non-midnight стадии deep/REM/core/unspecified/awake.
  3. Fallback: последний raw non-midnight sleep_total; затем слабый midnight summary sleep_total + sleep_awake.
  4. Отклонить candidate вне 03:00–15:00; новый поздний sleep fragment переносит candidate.
  5. Ждать candidate age ≥30 минут и ingest quiet ≥20 минут. ≥100 шагов после candidate даёт high confidence для detailed signal.
  6. Без шагов detailed candidate становится medium через 60 минут. Слишком ранний candidate ждёт до 90 минут либо typical wake −30 минут.
  7. Fallback signal без шагов ждёт не менее 90 минут и не получает high confidence.

Модель данных

derived_metrics хранит одну canonical row на (metric_name, metric_date), один typed value, state, formula version, inputs hash, calculated/finalized timestamps и metadata. Закрытый Go registry не позволяет превратить таблицу в произвольный EAV.

derived_metric_feedback хранит один вопрос/ответ на (metric_name, metric_date, channel). Первый callback сохраняется идемпотентно; повторный tap не меняет label или timestamp. Обе таблицы входят в tenant schema contract v6.

Интеграции

  • Scheduler и ingest-trigger вызывают ComputeMorningWakeStatus; all-day proxy в 300 шагов удалён.
  • Morning cap, check-in decision table и durable report delivery сохранены.
  • Ответ на subjective morning check-in записывается как passive awake evidence.
  • После отчёта medium/low wake candidate спрашивается в Telegram; high — контрольный вопрос не чаще раза в 7 дней.
  • Если wake-вопрос отправлен или transport неоднозначен, context prompt тем же утром не отправляется.
  • wake_feedback_enabled=false отключает новые вопросы.
  • GET /api/derived-metrics?metric=wake_time&from=...&to=... возвращает sanitized values без inputs hash и private metadata.
  • cmd/wake_detection_backfill dry-run по умолчанию; --apply пишет provisional historical rows без фиктивных confirmations.

Изменённые области

Storage и schema contract; wake detector/probe/backfill; morning scheduler и report sender; Telegram prompt/callback/i18n; public API/OpenAPI; Makefile; AGENTS.md и CLAUDE.md. Риски и rollback

  • Утренний короткий сон может сдвинуть candidate; для доставки это безопаснее преждевременного отчёта.
  • Summary-only источники имеют пониженную confidence.
  • Feedback labels в v1 только накапливаются; online learning отсутствует.
  • Runtime rollback возвращает старый image; additive tables не удаляются. Wake feedback отключается setting-ом.
