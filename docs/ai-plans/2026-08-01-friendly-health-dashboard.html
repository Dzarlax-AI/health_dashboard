Health Processing · Implementation Plan · 2026-08-01

Дружелюбный dashboard с качеством сна

Перестроить главный экран вокруг одного понятного совета на день, сохранить аналитическую глубину ниже и заложить общие визуальные примитивы для будущего обновления всего веб-интерфейса.

План одобрен · реализация выполнена в изолированной ветке

1. Результат и границы первой фазы

Входит в эту реализацию

  • Новый Today hero с утверждённым пейзажным фоном.
  • Одна консервативная рекомендация вместо конкурирующих вердиктов.
  • Готовность как главный показатель в hero; энергия и качество сна как поддерживающие показатели ниже.
  • Структурно стабильный SVG-компонент кругового показателя.
  • Более мягкие карточки и общие визуальные токены.
  • Сохранение alerts, AI insight, метрик, секций и недельной аналитики.

Не входит в эту реализацию

  • Редизайн Settings, Admin, login, import и metric detail.
  • Изменение формул Readiness или EnergyBank.
  • Новая медицинская интерпретация данных.
  • Миграция базы данных или новый сохранённый score.
  • Копирование мобильной навигации Bevel.

Dashboard станет первым потребителем общей дизайн-системы, но фон останется особенностью Today hero. Остальные страницы позже унаследуют типографику, поверхности, контролы и состояния — не пейзаж.

2. Что есть сейчас

  • internal/ui/templates/pages/dashboard.html показывает в одном hero независимые Readiness, Headline, EnergyBank и 30-дневный sparkline. Пользователь вынужден сам согласовывать их смысл.
  • internal/ui/handler.go::pageDashboard строит локальную анонимную view model и вручную переносит поля из health.BriefingResponse.
  • internal/health/energy_v2.go::SleepQuality уже содержит формулу качества сна: длительность × непрерывность × структура.
  • internal/health/sleep.go::computeSleepAnalysis сейчас возвращает преимущественно семидневные средние, поэтому отдельный same-night breakdown нужен для дневной карточки.
  • internal/ui/style.go содержит единый большой CSS string. Текущий readiness score — крупное число, а не геометрически зафиксированный круговой компонент.
  • internal/ui/render.go встраивает только static/*.js и всегда отвечает JavaScript MIME type. Перед добавлением изображения статический обработчик нужно сделать бинарно- и MIME-safe.
  • Тесты шаблона уже существуют в internal/ui/dashboard_illness_template_test.go; тесты формулы сна — в internal/health/energy_v2_test.go.

3. Контракты данных и логика

Качество сна

Формула остаётся единственной. Новый helper возвращает результат и компоненты, а существующий SleepQuality делегирует ему, чтобы EnergyBank и UI не разошлись. 

type SleepQualityBreakdown struct {
    ScorePct      *int   `json:"score_pct,omitempty"`
    DurationPct   int    `json:"duration_pct"`
    ContinuityPct *int   `json:"continuity_pct,omitempty"`
    StructurePct  *int   `json:"structure_pct,omitempty"`
    Confidence    string `json:"confidence"` // final | partial | missing | low
}

func ComputeSleepQualityBreakdown(
    totalH, deepH, remH, awakeH *float64,
    evidence ReadinessComponentEvidence,
) *SleepQualityBreakdown

Final требует same-night total, deep, REM и awake с допустимым evidence. При наличии только total возвращается partial без точного ScorePct. При отсутствии total возвращается missing. Нулевой score никогда не используется как замена отсутствующим данным.

Единая рекомендация

type DashboardTodayGuidance struct {
    Action     string    `json:"action"`     // rest | active_recovery | moderate | push_hard
    Label      string    `json:"label"`      // localized short label
    Summary    string    `json:"summary"`    // one actionable sentence
    Reason     string    `json:"reason"`     // concise supporting evidence
    Confidence string    `json:"confidence"` // final | provisional | low
    UpdatedAt  time.Time `json:"updated_at,omitempty"`
}

func ResolveDashboardTodayGuidance(
    energy *EnergyBank,
    readiness *ReadinessServingState,
    illness *IllnessSuspicion,
    sleep *SleepQualityBreakdown,
    ls LangStrings,
) *DashboardTodayGuidance
  1. Существующие illness safety caps остаются высшим приоритетом.
  2. rest и active_recovery никогда не повышаются UI-слоем.
  3. push_hard понижается до moderate, если Readiness missing, stale, provisional или low coverage.
  4. Partial/low sleep может только ограничить действие, но не повысить его выше EnergyBank verdict.
  5. При fresh/final данных сохраняется финальный EnergyBank verdict.

Последовательность вычисления

ComputeBriefing builds same-night SleepQualityBreakdown
  → storage applies EnergyBank v2 override
  → storage attaches subjective check-in and illness evidence
  → ApplyIllnessSafetyCap
  → ResolveDashboardTodayGuidance
  → EnrichLabels
  → handler maps a named DashboardPage view model
  → server-rendered template

Это важно: guidance строится после всех storage-level override и safety cap, иначе hero снова сможет противоречить фактическому EnergyBank.

4. Геометрический контракт кругов

Смещение круга считается блокирующей регрессией

Компонент не должен зависеть от длины текста, соседней колонки, локали или viewport. Никаких ручных translate, отрицательных margin или breakpoint-specific offsets. 

<div class="score-gauge__frame">
  <svg class="score-gauge__svg"
       viewBox="0 0 120 120"
       preserveAspectRatio="xMidYMid meet"
       role="img"
       aria-labelledby="...">
    <circle class="score-gauge__track" cx="60" cy="60" r="50"/>
    <circle class="score-gauge__progress"
            cx="60" cy="60" r="50"
            pathLength="100"
            stroke-dasharray="VALUE 100"/>
  </svg>
  <div class="score-gauge__content">…</div>
</div>
  • Wrapper: aspect-ratio: 1, одинаковые inline/block size.
  • Центрирование: CSS grid с place-items: center.
  • Размер: один bounded clamp(), без растяжения по контенту.
  • Track, progress, score и label используют один центр.
  • Readiness, Energy и Sleep используют один template partial.
  • Structural test фиксирует square wrapper, viewBox, preserveAspectRatio и отсутствие inline positional hacks.
  • Browser QA сравнивает центр и bounding box на ширинах 320, 375, 768, 1024 и 1440 px во всех локалях.

Автоматические сценарии

  • Идеальная, короткая, фрагментированная и stage-deficient ночь.
  • Только sleep_total → partial без точного score.
  • Нет same-night sleep → missing, без подстановки старого значения.
  • Low-confidence evidence → low state.
  • Illness cap побеждает любой положительный verdict.
  • Missing/provisional readiness ограничивает push_hard до moderate.
  • Final readiness сохраняет EnergyBank verdict.
  • Неизвестные enum не превращаются в сырые i18n keys.
  • Hero image имеет image/webp и cache-busted URL.
  • JS assets продолжают иметь JavaScript MIME.
  • Gauge partial содержит фиксированную геометрию и accessible name.
  • Существующие illness/readiness template tests остаются зелёными.

8. Manual QA

  • Fresh day: один совет и три score всего — Readiness в hero, Energy и Sleep ниже, без дублирования готовности.
  • Provisional readiness: score виден, confidence вторичен, push_hard не показывается.
  • Partial sleep: длительность видна, точный quality score скрыт.
  • Missing sleep: нет пустого/нулевого круга, показано спокойное объяснение.
  • Stale data: старое значение не выглядит свежим.
  • Illness suspicion: safety cap и alert остаются заметными.
  • No data: onboarding action вместо пустых gauge.
  • Фон не снижает контраст и корректно исчезает при ошибке загрузки.
  • Клавиатурой достижимы cards, details, nav и confidence disclosure.
  • Все status различимы без цвета.
  • EN/RU/SR не показывают raw keys и не ломают layout.
  • 320, 375, 768, 1024, 1440 px не создают горизонтальный scroll.
  • Центр readiness circle не меняется при длинной рекомендации.
  • Центр circle совпадает в fresh/provisional/partial/missing fixtures.
  • На dark-mode hero остаётся читаемым; аналитические карточки не становятся прозрачными.

9. Риски и защита

РискМера
Guidance вычислен раньше финального EnergyBank override. Создавать его в конце storage briefing path после safety caps; отдельный precedence test.
Сжатые metric slices подставляют прошлую ночь как сегодняшнюю. Confidence брать из date-aligned readiness evidence; missing не превращать в score 0.

Пейзаж ухудшает читаемость или dark mode. Постоянный readability wash, opaque fallback, contrast review.
Большое изображение замедляет первый экран. WebP, ограниченный размер, cache hash, явные width/height или aspect ratio.
Редизайн случайно скрывает глубокую аналитику. Template tests проверяют присутствие прежних section ids и links.
Новые общие CSS tokens ломают Admin/Settings. Токены additive; существующие aliases сохраняются. Smoke-check одной dense и одной form page.
Публичный JSON contract ломает клиентов. Только optional additive поля, существующие поля не переименовываются и не меняют тип.

10. Данные, безопасность и доставка

  • DB: миграция не требуется; score вычисляется из существующих sleep fields.
  • Auth/permissions: маршруты и tenant scoping не меняются.
  • API: только additive optional поля в BriefingResponse.
  • Privacy: фон не содержит health data; screenshots делаются только на synthetic review tenant.
  • Deployment: изображение встраивается в Go binary и отдаётся same-origin, без runtime CDN.
  • Cache: изображение участвует в существующем static hash и immutable cache policy.

11. Rollback и последующие фазы

Rollback выполняется возвратом dashboard template/CSS/view-model и прекращением заполнения новых optional response fields. Новых таблиц, миграций и необратимых записей нет. Исходные Readiness и EnergyBank остаются источниками истины.

После стабилизации dashboard отдельный план сможет перенести общие primitives на metric detail/history, затем Settings/import, затем Admin/login. Эта реализация не должна незаметно расширяться на эти страницы.

12. Предположения и открытые вопросы

  • Используется утверждённый morning-meadow visual; перед включением исходник оптимизируется в WebP без изменения композиции.
  • В hero показывается дата data frame из briefing. Относительное «обновлено N минут назад» выводится только если GetLatestMetricDate успешно вернул timestamp; иначе строка не фабрикуется.
  • Qualitative sleep bands остаются: 80–100 restorative, 60–79 good, 40–59 mixed, 0–39 poor. Это UX labels существующей формулы, не диагноз.
  • Первый выпуск меняет только dashboard composition; общие токены проектируются с учётом будущих страниц, но не применяются к ним массово.

Неразрешённых вопросов, блокирующих начало реализации после одобрения этого плана, нет.

14. Фактический результат реализации

Что изменено

  • Добавлен единый консервативный DashboardTodayGuidance, вычисляемый после EnergyBank override и illness safety cap. Медицински значимая причина cap не перезаписывается менее важным missing/stale состоянием.
  • Существующая формула SleepQuality стала источником breakdown: duration, continuity, structure и confidence. Partial или missing сон не превращается в точный нулевой score; stale REM и другие stage-сигналы участвуют в confidence.
  • Dashboard получил пейзажный Today hero, один план на день и общий SVG gauge partial. После обратной связи готовность показывается только в hero; ниже остались Energy и Sleep Quality.
  • Старые readiness/energy sparklines, hourly EnergyBank chart, methodology badges и EnergyBank components сохранены в компактном раскрываемом блоке «Детали».
  • Добавлены named dashboard view model, no-data onboarding, partial/missing sleep states, EN/RU/SR labels и accessibility fallbacks.
  • Статический обработчик теперь бинарно-safe и определяет MIME по расширению. Утверждённый фон оптимизирован в WebP (около 75 KB), встроен в Go binary и участвует в существующем static hash.
  • Для подготовки WebP локально установлены Homebrew packages webp и libtiff с их зависимостями.
