Issue #212 · 2 August 2026

Define a shared, tenant-safe API contract for web and mobile

Make the existing client API explicit and testable before the TypeScript frontend begins depending on it. Preserve current iOS paths and behavior.

OpenAPI 3.1 Existing /api paths No business-logic rewrite

Current behavior

Server

Client JSON is emitted by handlers in internal/ui. Several response envelopes are anonymous maps or handler-private types. Domain structs are serialized directly for larger responses.

Clients

The Go-rendered web UI and iOS app already call current /api/* paths. iOS sends X-API-Key; browser calls use ForwardAuth or the local session cookie.

Decisions

  • OpenAPI 3.1 JSON is the canonical machine-readable contract because it covers routes, query inputs, response schemas, content types, and security modes in one standard artifact.
  • Keep current paths. The real iOS app already consumes them. Adding /api/v1 aliases now would duplicate routing without enabling a migration.
  • Compatibility is additive by default. Removing a required field, changing its type or nullability, or narrowing an enum is a breaking change.
  • Backend owns tenant identity. The contract exposes no tenant or schema selector on user-facing client endpoints.
  • Phase-one machine coverage includes dashboard, health briefing, AI briefing, readiness history, and both EnergyBank history variants. The complete iOS endpoint inventory is documented with follow-up coverage status.

Desired behavior

  • Named transport envelopes live outside the template handler and are reused by handlers and contract generation.
  • A deterministic generator produces contracts/openapi.json from Go response types plus explicit route metadata.
  • A test regenerates the contract and fails when the checked-in artifact drifts.
  • Compatibility tests compare the current contract to a protected baseline for required fields, types, nullability, and enums.
  • Handler-level negative tests prove query or header input cannot override tenant context.
  • Documentation maps browser and iOS calls, security modes, locale rules, timestamps, partial data, and existing plain-text error responses.

Implementation steps

  1. Inventory real iOS and browser endpoint usage and record current path/auth behavior.
  2. Create named phase-one response envelopes in internal/api.
  3. Update handlers to emit those envelopes without changing response JSON.
  4. Build a deterministic OpenAPI 3.1 generator from Go schemas and explicit route metadata.
  5. Generate and check in the contract and reviewed compatibility baseline.
  6. Add drift, compatibility, schema validity, handler shape, and tenant override negative tests.
  7. Document client behavior and update architecture documentation in AGENTS.md/CLAUDE.md in lockstep if needed.

Test plan

  • make contract-check validates deterministic generation and backward compatibility.
  • Focused internal/api tests validate the OpenAPI document and protected response contracts.
  • Focused internal/ui tests verify JSON shapes and reject tenant/schema override attempts.
  • make test-unit proves current Go and UI behavior remains green.
  • go vet ./... and git diff --check cover static and formatting regressions.

Manual QA checklist

  • OpenAPI lists browser cookie and X-API-Key authentication as alternatives.
  • Supported locale values are exactly en, ru, and sr; invalid input falls back to English.
  • Optional health signals are nullable/optional without inventing values.
  • AI cold-cache state distinguishes generating, disabled, and populated content.
  • Energy day/hour variants are distinguishable by granularity.
  • No user-facing endpoint accepts tenant/schema identity from the client.

Risks and rollback

Risk

A generated schema may accidentally describe Go implementation details as required client behavior.

Avoid this by using named transport envelopes, reviewed enums, and a compatibility baseline rather than reflecting every handler automatically.

Rollback

This issue changes no database, deployment, or route ownership. Reverting the API package, handler envelope refactor, contract files, and Make targets restores the previous state.

Open questions resolved

  • OpenAPI is selected over a loose JSON Schema bundle.
  • Existing paths remain canonical; version aliases are deferred until a real breaking migration exists.
  • TypeScript client generation belongs to #213 and consumes this artifact.
