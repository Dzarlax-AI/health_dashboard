Current Behavior

  • ComputeUserVerdictBands currently requires at least 30 distinct eligible days before returning personal latest-formula or mixed compatible-formula bands.
  • When both latest and compatible samples are below 30 days, it returns default_warmup and exposes diagnostic day counts.
  • Stress drain is gated by settings.energy.stress_drain_enabled; with the default config, EffectiveBeta() is zero.
  • Stress load and flags are computed and stored in daily_scores.sustained_hr_load / stress_flags, and admin validation exists, but the dashboard/admin surface does not yet give a compact operational view for "is beta safe to enable".
  • internal/health already has tests for stress flags, labels, v2 verdicts, and some scoring helpers; coverage is still scattered rather than framed as formula invariants.

Experiment Result

Read-only experiments were run against two anonymized tenant patterns after the day-level calibration fix.

Profile B does not gain more days from a larger window, but the 22-day compatible sample looks less permissive than defaults. That supports a provisional 20-29 day mode if it is explicitly marked and guarded.

Desired Behavior

Stress Observability

Add a read-only summary that shows recent stress-load coverage, gating flags, distribution stats, and validation verdict so beta remains disabled until evidence says otherwise.

Health Invariants

Add targeted tests around pure formulas: readiness boundaries, EnergyBank v2 verdict ordering, stress coherence, strain/stress math, and invalid/missing input behavior.

Provisional Warmup

Allow a separately named provisional band mode only for 20-29 compatible days, with metadata that prevents confusing it with mature personal calibration.

Provisional Warmup Policy

  • Keep energyBandsMinPoints = 30 for mature personal modes.
  • Add a lower provisional threshold, proposed as energyBandsProvisionalMinPoints = 20.
  • Use the same energyBandsWindowDays = 180 window as mature bands. Do not extend the window for sparse tenants in this PR.
  • Use provisional mode only for compatible-formula samples, not unknown formula versions.
  • Mode name: provisional_compatible_formula_warmup. This avoids implying the sample is always mixed; the compatible sample may contain only the latest formula.
  • Source remains personal for compatibility, but CalibrationMode carries the precise semantics.
  • UsedDays and NDataPoints mean the provisional compatible distinct-date count.
  • Guardrail: provisional bands must not be more permissive than defaults at any decision boundary.
  • Clamp component-wise: Rest=max(computed.Rest, default.Rest), Recovery=max(computed.Recovery, default.Recovery), PushHard=max(computed.PushHard, default.PushHard).
  • Guardrail: preserve monotonic bands after clamping: Rest <= Recovery <= PushHard. If monotonicity breaks, fall back to default_warmup.
  • Do not change ChooseVerdictV2 or stress-flag override behavior in this PR.
  • Dashboard may consume provisional bands for verdict calculation, but main UI does not need a new badge in this PR.
  • Admin/API must expose CalibrationMode, UsedDays, LatestFormulaDays, and CompatibleFormulaDays.
  • Verdict text must not claim mature personal calibration when CalibrationMode starts with provisional_.

Stress Observability Scope

This PR should not enable beta and should not change the EnergyBank drain formula. It should make the existing stress data operationally inspectable.

  • Add a storage-level summary method over the recent stress window, likely reusing ComputeStressDistributionStats and existing validation read paths where possible.
  • Expose read-only admin JSON containing: window, dates with non-null load, empty days, load mean/median/p90/max, flag counts, validation verdict, and effective beta state.
  • Render a compact admin section near the existing stress validation and EnergyBank settings.
  • Clearly state when energy.stress_drain_enabled=false means beta is observed only, not applied.
  • Admin observability GET must not write, trigger backfill, recompute-and-cache validation, or mutate settings.
  • The endpoint may read existing validation cache. If fresh validation recomputation writes cache, keep it behind an explicit refresh action outside this PR or behind a separate non-GET endpoint.

Risks

  • Bundling three tasks can make the PR harder to review. Mitigation: enforce no cross-coupling, keep commits/file groups separated by concern, and split before implementation if the diff grows beyond the boundaries above.
  • Provisional 20-29 day bands can still be noisy. Mitigation: explicit mode, guardrails, and no claim of mature personal calibration.
  • Admin UI can accidentally imply beta is safe to enable. Mitigation: wording and API fields must distinguish observed stress load from applied drain.
  • Pure-math tests can overfit current constants. Mitigation: test invariants and precedence rules, not every exact output unless the constant is intentional API behavior.

Rollback Plan

  • Disable provisional warmup by raising the provisional threshold back to 30 or returning default_warmup from the provisional branch.
  • Leave pure-math tests in place unless they encode an incorrect invariant.
  • Remove or hide the admin observability section without changing storage tables or EnergyBank computation.
  • No database rollback is expected.

Open Questions
