Почему сегодня сон отличался от обычного

22 ноября 2026 · Редакция 1 · Реализовано и проверено локально на main.

Границы релиза

Today включает объяснение из той же версии результата, которую видит пользователь. Включение контролирует существующая настройка профиля. Утренний отчёт сохраняет текст, который был подготовлен при отправке. Объём разрешения охватывает локальную реализацию и синтетические проверки.

Текущее поведение

На main 45d34db Sleep и утренний отчёт уже читают GetSleepDurationComparison. Представление sleep_duration_reference_v1 использует LATERAL по диапазону предшествующих дат, ограниченному источником, эпохой и версией алгоритма. Это позволяет проверить реальный план прежде, чем менять SQL. Прежние 11 мс измеряли другую операцию.

Изменения и ответственность

  1. Клиент и транспорт Today получают необязательное сравнение с компонентами и локально раскрывают объяснение. Проверить холодное открытие, смену даты, выключенную настройку и недостаток данных. Основные пути — internal/ui, internal/api, apps/web.
  2. В experiments/dbt_metrics уточнить контракт YAML и связать с исполняемыми проверками правила SQL на 6 и 7 ночах, границах T−30, T−31 и дате пробуждения. На многолетнем синтетическом наборе посмотреть EXPLAIN (ANALYZE, BUFFERS). При существенном сканировании истории выяснить причину и обосновать параметризованный диапазон.
  3. В internal/notify подтвердить, что позднее изменение меняет актуальное сравнение, а чтение истории возвращает ранее сохранённое объяснение. Доставка только в локальный тестовый транспорт.

Отдельные исполнители ведут UI/API, контракт SQL и архив. Интеграционный обзор проверяет согласованность дат, версий, прав и отсутствие новой материализации.

Приёмка и откат

Проверить контракт OpenAPI, сборку и тесты web, сравнение в PostgreSQL, архив и повторное чтение. Различать длительность SQL и задержку HTTP. При отключении флага карточка исчезает, прежние отчёты доступны. Публикация и изменение настроек пользователей требуют отдельного разрешения.

Итоги реализации

Today получает необязательное поле sleep_duration_comparison через /api/health-briefing. Общая карточка Sleep и Today показывает длительность и знак отклонения словами. Объяснение Today раскрывается из ответа. Существующий флаг профиля управляет доступностью. Запрос выполняется в существующем представлении PostgreSQL при чтении.

На PostgreSQL 17.11 с 5000 синтетическими ночами запрос использовал индекс текущей даты и индексный диапазон на 30 предыдущих строках. Первый замер SQL составил 2,132 мс, следующие четыре — 0,060–0,076 мс. Это время исполнения SQL на локальной базе. Отдельный тест связывает объявленные в YAML окно и порог с поведением живого представления.

Тест HTTP через два изолированных профиля подтвердил исправление с −60 до −75 минут, новую версию факта и выключенный флаг второго профиля. Браузерный тест на ширине 390 px подтвердил раскрытие с клавиатуры, сохранение показанной версии и обновление после перезагрузки. Тест архива подтвердил прежние −51 минуту для отправленного текста и −42 для уточнённой истории. Пройдены Go-тесты, проверка контракта, тесты и сборка web. PR #286 вошёл в main и выпущен в production, ревизия 117c482. Штатный tenant gate и проверки обоих контейнеров прошли. HTML Today и связанный JS доступны. В основном профиле один запрос русского briefing занял 155 мс и вернул то же сравнение, что отдельный API Sleep. Повторное чтение архивного отчёта дало одинаковый результат. Проверка понимания объяснения пользователем и измерение задержки после естественной синхронизации остаются открытыми.

Проверка понятности

Пользователь открыл «Почему?» и отметил непонятную подпись «Версия методики sleep_duration_reference_v1». Исправление в PR #287 убирает служебный идентификатор из карточки, указывает окно в 30 дней и объясняет, почему поздняя синхронизация может изменить сравнение. Идентификатор правила остаётся в API. Пройдены 141 тест web и проверка раскрытия в Chromium. Веб-клиент выпущен в production на версии 8307cca. После выкладки проверены тексты загружаемого JS на трёх языках и обычный авторизованный ответ Today для основного профиля. Повторная оценка текста пользователем остаётся открытой.
