Deploy the frontend service and canary the dashboard route

Issue #217 adds the verified standalone frontend beside the single Go backend, canaries only / and /assets/*, and keeps immediate route-level rollback.

Current and desired behavior

Production currently routes every browser page, JSON API, ingestion request, and MCP call to one Go container. The desired stack keeps one Go backend for API/business logic and a separate static frontend. Browser /api/* receives trusted ForwardAuth headers; mobile/API-key calls preserve their direct API boundary; machine /health* and /mcp* retain API-key/bearer auth; every legacy page remains on Go.

Architecture decision

The local personal_ai_stack deployment mirror has no Git metadata and no corresponding accessible GitHub repository. Therefore the reviewable canonical manifest lives in health_dashboard/deploy/production/health. An approved deployment mirrors it to personal_ai_stack/deploy/health and the VPS without copying secrets back into Git.

Implementation

  1. Resolve the atomic health_dashboard-pair:compatible pointer and fail closed on digest, role, revision, contract, or architecture mismatch.
  2. Generate a non-secret release file for canary, cutover, or rollback; never hand-edit Traefik rules.
  3. Add one frontend container. Split machine, browser API, legacy UI, legacy-root alias, frontend root, and frontend assets into explicit priority-ordered routers.
  4. Validate all route modes with rendered Compose configuration and negative resolver cases.
  5. Canary in production for all locales and at least two tenants, rehearse rollback, then request approval before default cutover.

Tests and manual QA

  • Go tests and complete web contract/type/lint/unit/build checks.
  • Release resolver tests, Compose rendering for three modes, immutable digest checks, and shell syntax.
  • Container health/log checks; tenant-aware /api/session; legacy routes; ingestion and MCP auth; RU/EN/SR; mobile layout.

Risks and rollback

Primary risks are auth loops, route shadowing, mixed component releases, duplicate backend side effects, and tenant leakage. Rollback disables Traefik discovery for the frontend so the already-running low-priority Go router owns root again. No schema or data migration is part of this task.
