Текущая архитектура

React-приложение сейчас владеет только корневой страницей. /sleep рендерится Go-шаблоном templates/pages/section.html. Для новой страницы уже существуют почти все данные:

  • GET /api/health-briefing — состояние сна, quality score, средние и источники;
  • GET /api/section/sleep — локализованные summary, details, chart metadata и explanations;
  • GET /api/metrics/data — история фаз сна;
  • GET /api/derived-metrics?metric=wake_time — история определённого времени пробуждения.
  • GET /api/ai-briefing — сейчас читает AI-блоки только за сегодняшний день; активный v2 pipeline сохраняет один SYNTHESIS, а отдельные legacy SLEEP-блоки остаются у старых дат. Storage уже умеет читать их по произвольным date + lang.

Важное ограничение: если UI понадобится структурированное значение, которого нет в контракте, расширяем API и OpenAPI-схему. Парсинг строк вида «7 ч/ночь» запрещён.

Утверждённое изменение AI pipeline

Одиночный v2 SYNTHESIS слишком общий для detail pages. Возвращаем крупные смысловые блоки без возврата к четырём независимым запросам:

  1. Сервер собирает один детерминированный evidence packet с общим verdict/action и rule-based данными для sleep, activity/yesterday и recovery.
  2. Провайдер вызывается один раз и возвращает structured JSON: overview, sleep, activity, recovery, recommendation.
  3. Результаты сохраняются в существующие ключи SYNTHESIS, SLEEP, YESTERDAY, RECOVERY, RECOMMENDATION. Это сохраняет совместимость с Telegram, web и released iOS.
  4. Каждый текст валидируется отдельно: plain text, 1–2 коротких предложения, без Markdown/HTML, диагнозов и выдуманных метрик. Пустой или невалидный блок не затирает ранее сохранённый.
  5. Один generation fingerprint и точный evidence hash инвалидируют набор согласованно. Повторное чтение совпадающего кеша не вызывает AI.
  6. Текущий день сохраняет non-blocking single-flight и failure backoff. Прошлые даты доступны только для чтения и никогда не регенерируются.

Граница модели: AI объясняет уже вычисленные сервером факты. Он не меняет readiness, EnergyBank verdict, рекомендации политики или source selection.

Предлагаемый data flow

  1. Route resolver в React выбирает SleepPage для /sleep; главная остаётся без регрессий.
  2. Один loader параллельно запрашивает briefing, section metadata, необходимые phase series и derived wake history.
  3. Чистый buildSleepViewModel переводит API DTO в UI states: ready, partial, stale, unavailable.
  4. Компоненты получают только структурированные значения; локализованные summary/details отображаются, но не парсятся.
  5. Текущая и выбранная историческая ночь показывают все пять категорий. Отсутствующее значение обозначается как «нет данных»; sleep_unspecified подписывается «Сон без стадий» с пояснением об источнике.
  6. Hero всегда показывает актуальную ночь. Выбор точки в истории меняет только карточку выбранной ночи, а повторный выбор «Сегодня» возвращает к актуальным данным.
  7. Сегодняшний AI-инсайт расположен между деталями актуальной ночи и историей. Он использует уже существующий /api/ai-briefing, показывает generating/disabled/empty state и обновляется без блокировки страницы.
  8. После выбора даты UI запрашивает /api/ai-briefing?date=YYYY-MM-DD&lang=…. Для прошлой даты endpoint только читает сохранённые строки; async generation разрешена исключительно для server-local «сегодня».
  9. Исторический AI-текст загружается только для выбранной даты, а не сразу для всех 90 дней. Синтезированный v2-инсайт остаётся каноническим; для старых дат сервер возвращает совместимое объединение legacy blocks.
  10. На sleep page основной текст — новый блок SLEEP. Для старых дат без него допускается canonical summary/SYNTHESIS с честным общим заголовком.
  11. При недоступности необязательного ресурса страница остаётся полезной и показывает локальный partial-state вместо общего error screen.

Manual QA

  • С главной переход на Сон ощущается непрерывным по typography, radii, spacing и tone.
  • Главный вывод понятен без чтения графиков; числа не противоречат rule-based briefing.
  • Tooltip показывает конкретное значение, unit и дату; axes имеют читаемые подписи.
  • Переключатели 7/30/90 обновляют диапазон, выбор даты показывает согласованные duration/phases/wake данные именно этой ночи.
  • В структуре ночи и истории доступны deep, REM, core, sleep without stages и awake; отсутствующая категория не маскируется нулём.
  • Выбор исторической даты не меняет hero: верх страницы остаётся сводкой актуальной ночи.
  • У кругового quality score нет серой внешней обводки; остаётся только цветной индикатор.
  • Сегодняшний AI-инсайт виден до истории, не подменяет rule-based hero и появляется после фоновой генерации без layout jump.
  • У выбранной исторической ночи показывается сохранённый AI-инсайт на активном языке; дата без сохранённого ответа показывает спокойный empty state.
  • Provisional wake time визуально отличается от final и не выдаётся за точный факт.
  • Mixed sources и отсутствующие phases не создают ложную структуру сна.
  • Back, locale, theme, logout и legacy navigation сохраняют контекст.

Риски и edge cases

  • Слишком красивый hero скрывает данные. Ключевые факты остаются сразу под выводом; на mobile hero компактнее.
  • API дублирует presentation strings. UI не парсит их; новые числа добавляются только типизированными полями.
  • Разные источники сна. Отображаем canonical server result и source/confidence, не пересчитываем source priority в браузере.
  • Неполная ночь. Late fragments и provisional state видимы; графики не дорисовывают отсутствующие значения.
  • История разных метрик имеет пропуски. Карточка выбранной ночи показывает «нет данных» по конкретному полю, не переносит значение соседнего дня.
  • sleep_unspecified ошибочно воспринимается как отдельная полноценная фаза. UI называет её «Сон без стадий» и объясняет, что источник не предоставил deep/REM/core breakdown.
  • 90 дней перегружают график. График агрегирует только визуальное представление, а tooltip и выбранная ночь используют исходную дневную точку.
  • Просмотр истории случайно тратит AI-токены. Backend запрещает regeneration для любого date != today; frontend не может обойти это поведением запроса.
  • Инсайт сохранён на другом языке. Запрашиваем только активный lang; если строки нет, показываем отсутствие перевода и не генерируем исторический перевод.
  • Блоки противоречат друг другу. Все пять приходят из одного structured response на одном evidence packet; серверные verdict/action остаются единственным авторитетом.
  • Общий synthesis принимают за sleep-specific анализ. Новый день использует отдельный SLEEP; fallback на старый synthesis получает общий заголовок.
  • Компоненты становятся слишком абстрактными. Обобщаем только то, что уже нужно SleepPage; следующие sections расширяют primitives по фактической необходимости.

Rollback

Go handler и template для /sleep остаются без удаления. Route-level rollback отключает frontend ownership только для /sleep; база, алгоритмы и данные не меняются. Если потребуется API addition, оно должно быть additive и совместимо со старым frontend image.

Зафиксированные решения

  • Основная визуальная линия — вариант A «Спокойная ночь».
  • История доступна за 7, 30, 90 дней и за весь доступный период.
  • Показываем deep, REM, core, sleep unspecified и awake; total остаётся сводной длительностью, а не шестой фазой.
  • Сегодняшний AI-инсайт показываем отдельной карточкой сразу после актуальной структуры ночи и до истории.
  • AI снова формирует крупные блоки, но одним provider call: overview, sleep, activity/yesterday, recovery и recommendation.
  • Для выбранного дня показываем сохранённый AI-инсайт. Исторические просмотры никогда не инициируют новую генерацию.
  • Hero остаётся сводкой актуальной ночи; историческая дата раскрывается в отдельной компактной карточке.
  • У quality score нет серой внешней обводки.
