Restore dark theme and tighten the insight layout

The production canary is healthy, but the migrated dashboard no longer preserves the legacy theme behavior and wastes substantial horizontal space inside the personal-insight card.

Task summary

Bring back a complete dark palette and make the personal insight denser without changing routing, APIs, authentication, tenant isolation, data calculations, or AI content.

Current behavior

  • The legacy Go UI applies dark-mode before first paint from localStorage.theme or prefers-color-scheme.
  • The React entry page has no equivalent bootstrap.
  • React tokens and Recharts colors are light-only, and html forces a light color scheme.
  • Hero, glass panels, gauges, loading states, and chart tooltips contain additional light-only colors.
  • Insight paragraphs are correctly limited to a readable line length, but their parent card spans the full desktop container. Four sequential blocks occupy only the left half and make the card unnecessarily tall.

Desired behavior

  • Dark system preference selects the dark palette when there is no saved choice.
  • Saved light and dark preferences override the system preference exactly as in the legacy UI.
  • A compact three-state control in the header lets the user choose System, Light, or Dark without reloading the page.
  • The theme is applied before React and CSS render, avoiding a light flash.
  • Background, surfaces, hero artwork, rings, states, charts, and tooltips remain readable and visually consistent.
  • Dark mode uses a dedicated night rendering of the same meadow composition, rather than dimming the morning image into a muddy low-contrast background.
  • The existing light theme remains pixel-stable except for CSS-variable plumbing used by charts.
  • At wide desktop sizes, insight sections use a balanced two-column layout while keeping readable line lengths; narrow screens preserve the existing single-column reading order.
  • The actionable “plan for today” block receives clearer emphasis without changing its text.

Assumptions

  • The visible control uses the existing theme storage key: Light and Dark persist their values, while System removes the key and follows prefers-color-scheme.
  • The existing dark-mode HTML attribute remains the shared theme contract.
  • The morning meadow remains the light-theme source of truth. A non-destructive sibling asset preserves its composition while changing only time of day, lighting, atmosphere, and palette for dark mode.
  • The API section order remains authoritative. CSS layout may rearrange presentation only when the four known sections are present, while DOM reading order stays unchanged.

Likely file changes

  • apps/web/index.html and apps/web/public/theme-bootstrap.js — synchronous same-origin pre-render theme bootstrap compatible with the production CSP.
  • apps/web/src/components/ThemeSwitcher.tsx and AppHeader.tsx — accessible three-state theme control.
  • apps/web/src/i18n/index.ts — localized control and option labels.
  • apps/web/src/styles/tokens.css — semantic dark tokens and chart tokens.
  • apps/web/src/styles/index.css — dark treatment for artwork, glass, rings, and status surfaces.
  • apps/web/src/assets/night-meadow-hero.webp — generated night-time counterpart to the existing morning meadow.
  • apps/web/src/components/charts/chartTheme.ts and TrendChart.tsx — consume semantic CSS variables.
  • apps/web/src/features/dashboard/DashboardDetails.tsx — add a semantic wrapper and section key hooks for the insight grid.
  • apps/web/tests/visual/theme.spec.ts — system and saved-preference regression coverage.
  • apps/web/tests/visual/insight-layout.spec.ts — desktop density, DOM order, and mobile reflow coverage.

Implementation steps

  1. Add a synchronous, storage-safe same-origin bootstrap matching the legacy precedence rules without requiring unsafe-inline in the production CSP.
  2. Add an accessible segmented radiogroup to the header. Apply changes before paint, persist only explicit Light/Dark choices, and subscribe to system-theme changes only while System is active.
  3. Add dark semantic tokens while preserving all light defaults.
  4. Replace remaining light-only chart colors with semantic variables.
  5. Generate a night variant from the existing meadow, preserving framing, hills, vegetation, negative space, and crop-safe edges; save it as a separate project asset.
  6. Add targeted dark overrides for translucent components and switch hero artwork to the night asset.
  7. Wrap AI sections in a responsive grid: two equal columns on wide screens, one column below the desktop breakpoint.
  8. Keep ordinary sections compact and turn the recommendation section into a visually distinct action block without adding decorative content.
  9. Run focused browser tests, then the complete web check and visual suite.
  10. Render desktop and mobile fixture views in light and dark modes and inspect console output.

Manual QA checklist

  • Desktop and mobile: no flash of the wrong theme.
  • The switcher fits the existing header hierarchy, exposes a clear selected state, and remains keyboard accessible without crowding navigation or locale controls.
  • Hero background remains visible; recommendation copy and readiness ring remain legible.
  • Night artwork matches the morning meadow's composition and crop across desktop and mobile, with no visible seam when the theme changes.
  • Supporting score cards, alerts, empty/loading/error states, and chart tooltips have sufficient contrast.
  • Insight card uses its width without stretching paragraphs into hard-to-read long lines.
  • Recommendation is visually discoverable and no section divider creates an orphaned line or uneven row.
  • Switching RU/EN/SR does not reset the selected theme.
  • No relevant console errors or warnings.

Risks

  • A deferred or bundled bootstrap could allow a flash of the wrong theme. Keep the small external script parser-blocking in <head>; the current script-src 'self' policy permits it.
  • Hard-coded light colors may escape the initial audit; repository-wide color search and visual QA mitigate this.
  • Dark chart tooltip styling depends on CSS custom properties supported by the current Recharts/browser baseline.
  • A generated night asset may drift from the established illustration or composition; side-by-side inspection at the actual hero crop is required before it can ship.
  • A two-column visual layout can create a misleading reading order if implemented with CSS reordering; the implementation must preserve DOM order and avoid explicit order values.

Rollback plan

Revert the frontend-only commit and rebuild the compatible image pair. The current canary remains usable on the previous frontend digest; no database or backend rollback is required. The insight layout can also be rolled back independently by removing its wrapper classes and responsive grid rules.

Open questions

No blocking questions. A visible three-state theme control (system/light/dark) can be considered separately after restoring parity.

  • Added an accessible three-state header switcher for System, Light, and Dark. It updates before paint, persists explicit choices, removes the override for System, and follows later operating-system changes while System is selected.
  • Added semantic dark tokens and switched Recharts grid, text, line, and tooltip colors to those tokens.
  • Generated and added apps/web/src/assets/night-meadow-hero.webp at the same 1600×772 dimensions as the morning source; dark hero and standalone states now use it.
