Migrate the main dashboard to TypeScript

Replace the deterministic foundation mock with a live, tenant-safe React dashboard that preserves the current health semantics, friendly morning background, compact hierarchy, asynchronous AI behavior, and all links into the still-supported Go pages.

Summary and boundary

In this issue

  • Live readiness, Energy Bank, sleep quality, guidance, freshness, alerts, briefing sections, metric cards, and AI briefing.
  • Friendly responsive layout with one readiness ring and compact supporting scores.
  • Recoverable loading, partial, stale, no-data, unauthenticated, and API-error states.
  • Links to existing Go routes for sleep, cardio, activity, recovery, metrics, settings, admin, and logout.
  • Build-only deterministic fixtures and regression coverage.

Not in this issue

  • No production route switch, frontend container, Traefik change, or deploy.
  • No rewrite of scoring, Energy Bank, sleep calculations, notification logic, auth, or tenant routing.
  • No migration or deletion of Go detail pages, templates, static assets, or Chart.js surfaces.
  • No client-side tenant/schema selector.

Current behavior

  • apps/web/src/App.tsx renders hard-coded readiness, energy, and sleep fixtures selected by ?fixture=.
  • The Go renderer uses /api/health-briefing semantics indirectly through health.BriefingResponse and presents the readiness ring once in the hero.
  • /api/health-briefing returns immediately and never waits on Gemini; /api/ai-briefing is polled separately.
  • readiness_serving.status is the canonical freshness state: fresh, missing, stale, data_accruing, low_coverage, or capped.
  • Sleep quality may be final, low-confidence, partial, or missing. A partial duration signal must not become a fabricated precise score.
  • The backend already protects every API and legacy page with tenant-aware auth. Redirected HTML is converted to a 401-like ClientApiError by the typed web client.
  • The React workspace is not served in production; the Go dashboard remains the live route and rollback source.

Desired behavior

  1. Load the localized health briefing as the required resource; load freshness metadata and trend history independently so an optional failure cannot erase useful health data.
  2. Show the readiness score exactly once, centered in the morning-meadow hero, with server-provided guidance and a secondary confidence badge.
  3. Show Energy Bank and sleep quality as compact supporting scores. Clamp only visual geometry; preserve the server’s textual verdict.
  4. When sleep quality is partial, show duration progress and uncertainty without inventing score_pct.
  5. Keep stale or incomplete warnings subordinate when the response still contains a usable date and score.
  6. Expose safety-relevant alerts, moderate/high illness suspicion, and localized Energy Bank flag details before optional trend depth.
  7. Render AI sections when cached, a quiet generating state when cold, nothing when disabled, and retry polling only while visible.
  8. On authentication expiry, offer a login link whose safe next value points back to the current dashboard URL. On retryable errors, provide an in-place retry.
  9. Keep all legacy page links same-origin and preserve lang=en|ru|sr.

Architectural decisions

Data source

/api/health-briefing is the required source. /api/dashboard, /api/readiness-history, and /api/energy-history are optional resources and cannot turn a usable briefing into a full-page error.

Tenant safety

Every request stays same-origin and carries only documented presentation parameters. No schema, tenant, tenant ID, proxy identity header, or API key is accepted from React.

Fixtures

Production builds always call the live API. ?fixture= is honored only when Vite builds in fixtures mode. This prevents a public URL from displaying plausible but fake health data.

Rollback

The Go dashboard route and renderer remain unchanged. Issue #217 will canary routing and define the explicit route-level rollback; #214 produces no production routing mutation.

Component ownership

App remains composition glue. Repeated visual patterns live in shared primitives; dashboard behavior lives in feature components; API loading and health semantics stay outside JSX. Variants are explicit props rather than copied markup or one-off CSS.

Charts

Use pinned recharts@3.10.1 with ResponsiveContainer, LineChart, and shared tooltip/axis styling. Chart components accept normalized data and presentation props so readiness and Energy Bank reuse the same chart foundation.

State model

type DashboardBundle = {
  briefing: HealthBriefingResponse;
  summary?: DashboardResponse;
  readinessHistory?: ReadinessHistoryResponse;
  energyHistory?: EnergyHistoryDayResponse;
};

type DashboardState =
  | { status: "loading" }
  | { status: "ready"; data: DashboardBundle }
  | { status: "partial"; data: DashboardBundle; reasons: readonly string[] }
  | { status: "stale"; data: DashboardBundle; lastUpdated?: string }
  | { status: "unavailable"; reason: "no_health_data" }
  | { status: "unauthenticated"; loginPath: string }
  | { status: "error"; message: string; retryable: boolean };

function classifyBriefing(bundle: DashboardBundle): DashboardState {
  if (!bundle.briefing.date) return { status: "unavailable", reason: "no_health_data" };
  const serving = bundle.briefing.readiness_serving?.status;
  if (serving === "stale") return { status: "stale", data: bundle };
  if (serving && serving !== "fresh") {
    return { status: "partial", data: bundle, reasons: [serving] };
  }
  return { status: "ready", data: bundle };
}

These names and invariants are the implementation contract: only an empty briefing date produces the no-data page; stale/partial data remains renderable; optional history failures do not erase the hero.

Risks and mitigations

Health-semantic drift

Mitigation: pure model tests mirror the existing Go template tests and prefer server enums/labels over duplicated thresholds.

Fake production data

Mitigation: fixture query support is compile-mode gated and Playwright owns the only fixture build.

One optional request blanks the page

Mitigation: health briefing is the sole required call; summary/history/session use independent settled results.

Auth redirect parsed as JSON

Mitigation: keep the existing redirected/HTML detection and test login recovery explicitly.

Mobile contract regression

Mitigation: only additive OpenAPI changes; protected compatibility baseline and generated Swift-facing contract remain unchanged otherwise.

Accidental route cutover

Mitigation: no Docker, compose, proxy, Go page route, or deployment file changes are allowed in #214.

Rollback plan

  1. Before #217, no production rollback is necessary because the React app is not routed in production.
  2. If #214 introduces an API regression after its backend image is eventually deployed, restore the previous immutable backend digest; the new session endpoint is additive and requires no database rollback.
  3. Do not remove or rewrite internal/ui/templates/pages/dashboard.html, dashboard_view.go, or their tests.
  4. During #217 canary, route the dashboard back to the existing Go service without changing the database.

  • Charts: use pinned Recharts 3.10.1 through a shared typed wrapper; do not configure one-off charts inside dashboard panels.

Implementation result · 2 August 2026

What changed

  • Added additive, authenticated GET /api/session with only is_admin; contract version is now 0.2.0.
  • Made legacy guard context explicitly admin so legacy and multi-user session capabilities share one context invariant.
  • Replaced the fixture-only App with live API loading and a pure dashboard view model.
  • Split header, status badge, hero, supporting scores, details, and charts into reusable components.
  • Added pinned Recharts 3.10.1 behind a lazy shared TrendChart wrapper and kept the fixed SVG readiness gauge.
  • Kept fixture selection behind VITE_ENABLE_FIXTURES=true; an ordinary production build ignores ?fixture=.
  • Preserved the accepted meadow background and compacted Energy Bank and sleep into useful summary cards.

Behavioral details

  • /api/health-briefing is the sole required call; optional dashboard, AI, history, and session failures degrade independently.
  • Readiness uses readiness_today once. Missing data never fabricates a score.
  • Signed Energy Bank values keep their raw text while the circular visual clamps to 0–100.
  • Provisional sleep shows duration without inventing a sleep-quality percentage.
  • AI regeneration polling runs only while visible, covers cold caches before the generating flag appears, and stops after ten attempts or when content arrives.
  • Recharts is code-split: the initial production JS chunk is about 220 KB instead of about 571 KB before splitting.
