React-primary dashboard и безопасный retirement Go UI

Нужно явное одобрение перед implementation

Задача

Не поддерживать две равноправные реализации пользовательского dashboard. React должен быть единственной активно развиваемой оболочкой для dashboard и его detail-экранов; Go остаётся backend/API, а его HTML-страницы не получают новых UX-изменений.

Подтверждённое текущее состояние

  • Живая страница /?lang=ru использует React-класс today-insights__domain; Go-шаблон использует другой класс today-insights-domain.
  • Production cutover уже направляет /, /sleep, /activity, /cardio, /recovery и /assets/* на frontend; backend остаётся владельцем /api/*, /health* и /mcp*.
  • Go всё ещё обслуживает /metrics, /metrics/{name}, /settings, /admin, /static/* и явный rollback URL /legacy.
  • Найденный UX-дефект в React Today Insights: sleep-card выводит один факт дважды, потому что summary и insight.observation сейчас равны.

Решение границы

Рекомендуемый scope: сейчас прекращаем parity-работу над Go dashboard и исправляем инсайты только в React. Go HTML остаётся временным route-level rollback для уже перенесённых пяти экранов и владельцем ещё не перенесённых metrics/settings/admin. Физически удалять Go renderer, templates или static assets в этом этапе нельзя: это уничтожит проверенный rollback и смешает UX-улучшение с миграцией административных экранов.

Целевое поведение инсайтов в React

ЭлементПравило
Главный блокОдин server-owned вывод, его смысл и разрешённый следующий шаг.
Сон / восстановление / энергияОдин факт плюс отдельная интерпретация только при фактическом, относящемся к дню сравнении или сигнале.
Недостаточные данныеПоказать состояние и один факт при наличии; не делать общий совет и не повторять строку ради заполнения карточки.
AIАсинхронно объясняет разрешённый server-owned вывод; не меняет действие, факт или ownership evidence.

Предлагаемые шаги

  1. Зафиксировать в DailyInsightDomain различие между фактом и интерпретацией; не подставлять один текст в оба поля.
  2. Для сна показывать длительность как факт и добавлять смысл только при доступном baseline/quality/freshness signal. Аналогично проверить recovery и energy на повтор primary headline.
  3. Обновить React TodayInsights: не рендерить второй текст, если он пуст или совпадает с фактом; не делать это UI-only маскировкой для различающихся, но бессодержательных текстов.
  4. Не менять Go template и не создавать новую parity-работу для него. Оставить его как rollback snapshot без новых product claims.
  5. Подготовить отдельный follow-up по миграции /metrics и metric-detail в React. Только после coverage всех нужных browser routes и периода стабильной эксплуатации решить физическое удаление Go page renderers.

Вероятно затрагиваемые файлы

  • internal/health/daily_insights.go — детерминированные факт и интерпретация, evidence и states.
  • internal/health/*_test.go — non-duplicate, baseline, stale/partial и локализационные fixtures.
  • apps/web/src/features/dashboard/TodayInsights.tsx и тесты — корректный visual hierarchy и conditional rendering.
  • apps/web/src/i18n/index.ts — только при необходимости новых коротких локализованных фраз.
  • docs/CLIENT_API.md, generated contract — только если для различения факта и интерпретации потребуется additive transport field; сначала предпочесть существующую форму.

Проверки и ручная приёмка

  • Focused Go tests для deterministic snapshot, включая sleep duration без baseline, non-uniform baseline, stale/partial sleep и RU/EN/SR.
  • make contract-check и make web-check; при изменении contract — generated artifacts только через штатную команду.
  • Playwright/visual checks для desktop и mobile: карточка никогда не содержит две идентичные строки.
  • В живом browser path: root, три detail links, cold/generating/disabled/failed AI state, смена RU/EN/SR и session recovery.
  • Перед будущим physical retirement: подтверждение, что /metrics, settings и admin имеют согласованные owners, и отдельная репетиция rollback.

Риски, rollback и открытые вопросы

  • Нельзя подменять отсутствующее baseline-сравнение придуманием смысла: в таком состоянии показывается факт или «контекст ещё уточняется».
  • Удаление Go HTML сейчас сломает /legacy rollback и ещё живые routes. Этот этап не меняет Traefik, Docker, DB или Authentik.
  • Открытый product choice для следующей миграции: переносим сначала /metrics с detail pages или оставляем их Go до отдельной redesign-задачи.
  • Rollback этого этапа — откатить React/insight commit; production routing и data остаются без изменений.

Approval gate

Approved for the React-primary insight scope. Physical removal of the Go renderer and migration of metrics/settings/admin remain separate decisions.

Implementation update

  • Implemented the server-side distinction between a factual card line and a separate, evidence-based interpretation. Sleep now compares the latest duration to the personal average when available; recovery shows its score before its guidance; energy shows current reserve before its verdict reason.
  • React suppresses an empty or duplicate supplementary line, protecting users during a cached response or a staggered frontend/backend rollout.
  • Addressed two live visual findings in the React surface: the dark-theme action chip now uses a dark, bordered surface with readable text, and supporting score gauges no longer add a decorative frame around the data ring.
  • Added focused snapshot and React regressions for non-duplicate cards and the no-context sleep case. No Go template, Traefik, deployment, database, or Authentik change was made.
  • Checks: go test ./internal/health ./internal/ui -count=1, make contract-check, and make web-check passed with GOCACHE=/private/tmp/health-insight-go-build.
