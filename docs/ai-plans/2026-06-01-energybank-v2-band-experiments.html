EnergyBank v2 Band Experiments

Implemented after approval

Task Summary

Correct the EnergyBank v2 verdict-band calibration path using read-only experiments on two anonymized tenant patterns. The goal is to decide how personal bands should be sampled before changing production code.

This plan intentionally does not contain tenant names, schema names, or personal identifiers. Profiles are labelled Profile A and Profile B.

Previous Behavior

  • GetHealthBriefing builds a legacy v1 EnergyBank, then overrides it from v2 snapshots when a snapshot exists for the requested date.
  • The v2 override calls ComputeUserVerdictBands, ChooseVerdictV2, BuildVerdictReasonV2, then stress-flag overrides.
  • ComputeUserVerdictBands computed percentiles over eligible energy_snapshots rows directly.
  • Because multiple intraday snapshots exist for the same local date, active/live days can count many times in the percentile distribution.

Experiment Setup

  • Read-only SQL against production snapshots.
  • Window: last 180 days, matching energyBandsWindowDays.
  • Eligible rows exclude imputed_sleep, imputed_activity, and bootstrap_tail.
  • Compared four sampling strategies: row-weighted all formulas, latest-row-per-day all formulas, row-weighted latest formula, latest-row-per-day latest formula.
  • Backtest verdicts used the same HRV gate order as ChooseVerdictV2, with HRV z-scores reconstructed from daily HRV against a trailing baseline.
  • Verdict-impact tables are pre-stress-override: they do not apply illness/recovery-debt/rebound overrides from ApplyStressFlagVerdictOverride.

Experiment Takeaways

Intraday overweighting is real

Row-weighted sampling raises thresholds sharply in both profiles. The effect is not profile-specific.

Profiles differ

Profile B has a higher day-level push threshold than Profile A, so personal bands still matter after fixing the sampling unit.

Latest formula is immature

Latest-formula day counts are 19 and 17, below the current documented 30-day gate.

Defaults are not neutral

Default bands produce more push_hard, especially in Profile B, so strict fallback may be too permissive during warmup.

Recommended Decision

Fix the sampling unit first: one local date should count as one data point, using the latest eligible snapshot for that date. Do not keep row-weighted bands.

For formula-version handling, use a conservative hybrid rule:

  1. Prefer latest-formula day-level bands when latest formula has at least 30 distinct eligible days.
  2. Before 30 latest-formula days, use compatible-formula day-level bands only if there are at least 30 distinct eligible days and those formula versions are explicitly whitelisted as comparable for warmup.
  3. If neither condition holds, fall back to defaults with CalibrationMode=default_warmup. Do not let NDataPoints or UsedDays imply the default bands were computed from those days.

This avoids the current row-weighting bug while also avoiding a too-permissive default-only warmup for profiles whose real day-level distribution is higher than defaults.

Formula Compatibility Policy

  • Compatible formula versions must be explicitly listed in code.
  • Unknown, empty, or unlisted formula_version values are not compatible by default.
  • The current formula version is always compatible with itself.
  • Mixed warmup is allowed only across versions whose bank distributions are expected to be comparable.
  • The compatibility list must be updated intentionally whenever formula behavior changes.

Implementation should make this policy visible in a small helper or whitelist rather than relying on broad numeric comparisons such as "all versions less than current".

Approved initial compatibility: formula_version=1 may warm up formula_version=2 only under the current non-stress-drain configuration where StressDrainEnabled=false and EffectiveBeta()==0, and only while the effective alpha coefficient still matches the default v1/v2-compatible coefficient. This is conditional compatibility, not a permanent {1,2} whitelist. If stress drain becomes active, or formula parameters change bank distribution materially, version 1 must stop contributing to version 2 warmup.

Suggested helper shape: 

compatible := map[int]bool{
    cfg.FormulaVersion: true,
}

if cfg.FormulaVersion == 2 &&
    !cfg.StressDrainEnabled &&
    cfg.EffectiveBeta() == 0 &&
    cfg.EffectiveAlpha() == DefaultEnergyConfig().EffectiveAlpha() {
    compatible[1] = true
}

Calibration Metadata Semantics

The implementation should not hide mixed-formula warmup behind ordinary personal source semantics. Explicit metadata is part of the fix, not optional documentation:

  • CalibrationMode: personal_latest_formula, personal_mixed_formula_warmup, default_warmup, or default.
  • UsedDays: distinct eligible local dates actually used to compute the returned bands.
  • LatestFormulaDays: distinct eligible local dates available for the current/latest formula.
  • CompatibleFormulaDays: distinct eligible local dates available after applying the compatibility whitelist.

If NDataPoints is retained for compatibility, it must mean distinct eligible dates used for returned non-default bands, never raw snapshot rows. In default modes, UsedDays should not imply that defaults were computed from local data; expose LatestFormulaDays and CompatibleFormulaDays separately for debugging.

Implementation Steps

  1. Add tests that fail under row-weighted sampling: many intraday rows for one date must count as one datapoint.
  2. Add tests for latest-formula <30 days with compatible-formula day-level fallback.
  3. Add tests proving imputed/bootstrap rows are excluded before per-date latest-row selection.
  4. Add a same-date, cross-formula test proving mixed warmup still counts one date once, not once per formula.
  5. Add a latest-formula-wins test: when latest formula has at least 30 dates, do not use mixed warmup even if compatible history is larger.
  6. Add a default-warmup test: when latest and compatible samples are both below 30 distinct dates, return defaults and mark warmup clearly.
  7. Add an unknown-formula test: rows from unknown or unlisted formula versions are excluded from compatible-formula warmup.
  8. Add count/source tests: date counts must never equal raw row counts when multiple snapshots exist for one date.
  9. Add a display-clamp test: percentiles must use bank values clamped to [0,100].
  10. Implement day-level sampling using latest eligible ts_bucket per date.
  11. Return metadata that distinguishes personal_latest_formula, personal_mixed_formula_warmup, and default_warmup.
  12. Run focused storage tests and full go test ./....
  13. After approval and implementation, run the same anonymized experiment query again to confirm row weighting is gone.

Risks

  • Using compatible-formula day-level warmup may still mix distributions across formula versions if compatibility is over-declared.
  • Using defaults only may over-permit push_hard for profiles whose real distribution sits above defaults.
  • Changing VerdictBands.Source strings can affect downstream consumers if they assume a closed enum.
  • Small latest-formula samples can still be noisy; avoid interpreting 17-19 days as final calibration.

Rollback Plan

  • Revert ComputeUserVerdictBands to default-only fallback if mixed-formula warmup behaves poorly.
  • Keep the day-level sampling fix even if formula-version policy changes; row-weighted calibration should not return.
  • No schema rollback is expected.

Implementation Update

Implemented after approval. ComputeUserVerdictBands now samples one latest eligible snapshot per local date, filters imputed/bootstrap rows before per-date selection, prefers current-formula personal bands at 30 distinct days, and falls back to compatible-formula warmup only through an explicit compatibility helper.

  • formula_version=1 warms up formula_version=2 only when StressDrainEnabled=false, EffectiveBeta()==0, and the effective alpha matches the default v1/v2-compatible coefficient.
  • Unknown or unlisted formula versions are excluded from compatible warmup.
  • VerdictBands now exposes CalibrationMode, UsedDays, LatestFormulaDays, and CompatibleFormulaDays.
  • NDataPoints now means distinct eligible dates used for returned non-default bands; default warmup returns NDataPoints=0.
  • Legacy Source remains personal or default for compatibility; precise semantics live in CalibrationMode.

Decision

Approved and implemented. Recommended implementation was applied: day-level sampling first, compatible-formula day-level warmup only when latest-formula days are below 30 and compatible day-level sample is at least 30, and compatible-formula warmup is not reported as ordinary personal calibration.
