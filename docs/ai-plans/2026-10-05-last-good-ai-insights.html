Сохранять последний готовый AI-инсайт

Утверждён пользователем «Го» · 5 октября 2026. Ветка codex/sleep-completeness-fix от выпущенной main. Уже готовый локальный fix полноты сна сохраняется; Расширение реализовано локально; результаты проверки ниже.

Требование и наблюдаемое поведение

Пользователь: «Если AI инсайт устарел, нужно показывать устаревший AI инсайт, пока не появится новый».

Сейчас сервер допускает только ready-текст с точным текущим hash и fingerprint. iOS visibleAI дополнительно требует ready/fresh, а при cold/generating рисует только ожидание. Сохранённый текст физически остаётся после смены hash, но прежняя валидная генерация может быть потеряна при invalidation или успешном null. В новом дне текущий lookup не находит вчерашний текст.

Желаемое поведение: каждый из overall/sleep/recovery/energy показывает последний успешно принятый текст до появления нового успешно принятого непустого текста. Подпись: «Предыдущий AI-инсайт от … · обновляется» либо «… · обновление не удалось». Дата и время относятся к самому тексту. Смена суток, повторный sync, ошибка провайдера и перезапуск не создают пустую карточку при наличии сохранённого текста.

Контракт и границы

  • Хранить tenant-local last-good запись по языку и slot: исходный ответ, дата, время успешного сохранения, исходные hashes и версия контракта. Записывать атомарно только после успешной проверки и текущего CAS/lease. Не обновлять время от polling.
  • Добавить явную информацию о показанном AI: fresh/stale, исходные дата/время; generation.state остаётся состоянием нового запроса. Предыдущий текст не обозначать ready для текущего snapshot.
  • Устаревший текст и его alternative action остаются видимыми как предыдущий ответ. Не использовать его как свежий факт, sibling для нового overall, текущий plan или доказательство нового решения.
  • Fallback только в том же tenant, языке и slot, в совместимом AI-контракте. Настройки явного отключения AI соблюдаются. Если успешного текста ещё никогда не было, показывать честное состояние первой генерации: отсутствующий ответ нельзя создать из ничего.
  • Валидный null новой генерации не стирает last-good. Ошибки новой генерации также его не стирают. Исторические cache-only запросы не вызывают провайдера.
  • Проверить legacy /api/ai-briefing: не маскировать старый план под свежий; предыдущую прозу выдавать с явной датой и устареванием. Никаких новых medical claims или изменений формул.

Проверки и риски

Начальный ready → sync → cold/generating: прежний текст виден с неизменным source timestamp. Failed/backoff/лимит polling: текст остаётся, бесконечный spinner заменён честным статусом; после завершения бюджетного polling допускается редкая проверка результата без сброса backoff. Новый ready заменяет только свой slot атомарно. Старый lease не публикует устаревший результат. Смена дня/языка/tenant, explicit disable и новый контракт не смешивают ответы. Подтверждённый null не выдаётся за новую рекомендацию. Полная ночь утром сохраняет доступность sleep AI.

Главный риск — предыдущий совет выглядит актуальным. Убираем это явной датой/маркировкой и сохранением текущего Server Insight отдельно. Старая версия клиента может продолжить скрывать fallback: пользовательский путь требует выпуска клиента, одного backend недостаточно.

Rollback: отменить чтение fallback и UI отображение, сохранить tenant-local записи history в settings. Выпуск выполняем только через согласованный PR/release; этот план не разрешает production mutation.

dbt v2: проверка гипотезы

Наш закреплённый runtime: dbt-core 1.12.5 + dbt-postgres 1.11.0. dbt v2 GA — Rust-движок, снижает framework/compile overhead; это не измерение ускорения PostgreSQL-запросов. Официальная матрица адаптеров не перечисляет PostgreSQL; issue Postgres support остаётся открытым при проверке 5 октября.

Не заменять закреплённый v1. После отдельного подтверждения возможности запуска — добавить изолированный compatibility smoke для закреплённого Rust binary и synthetic PostgreSQL. При unsupported adapter зафиксировать отказ и завершить; не подменять PostgreSQL Redshift/DuckDB и не выдавать другой backend за сопоставимый benchmark. Если поддержка работает: те же fixtures, девять data tests, известные различия, full/one-old-day, отдельные process/compile/SQL timings для Go/v1/v2. Без production данных и учётных данных.

Фактическая реализация и проверка

Last-good хранится в существующей tenant-local settings, ключи по языку/slot; новая таблица и миграция схемы не потребовались. Публикация атомарна с fenced сохранением текущей генерации. Совместимая принятая проза старого кеша переносится лениво; её дата известна, время генерации не выдумывается из времени polling. История добавляется после расчёта новых provider packets и siblings. Ошибка чтения history не скрывает текущие факты.

Web и iOS показывают предыдущий текст с датой и stale-статусом; null и failed не стирают его. После 10 активных polling попыток проверка замедляется до 5 минут с сохранением более длинного server backoff. Legacy API получил отдельное previous; оно не выдаёт текущий actionable plan. Полная ночь сохраняет собственную completeness при предварительном вечернем паттерне.

Проверено: go test ./..., contract-check, web-check (типы/lint/unit/build), iOS simulator InsightParityTests. Отдельный owned PostgreSQL 17.11: accepted → changed hash → failure → null → next day → replacement, stale lease, язык, invalidation, новый экземпляр сервиса, перенос pre-release кеша без выдуманного timestamp. Контейнер и volume удалены после тестов. Изоляция использует существующие tenant request pools; новые роли/ACL не вводились.

dbt 2.0.6: официальный бинарник в отдельном временном venv; debug со synthetic PostgreSQL профилем завершается dbt1005 до соединения. Экспериментальные адаптеры выключены. Benchmark не запускался, v1 runtime сохранён. Результат и воспроизводимый script описаны в experiments/dbt_metrics/README.md.

Ограничения: реализация проверена локально; пользователь разрешил подготовку PR и выпуск ответом «Давай»; production пользовательский путь и реальная синхронизация после этих исправлений ещё не проверены. Для iOS нужен выпуск клиента. Нет успешного прежнего текста — нечего показывать до первой успешной генерации. Существующие несвязанные изменения iOS локализации сохранены.
