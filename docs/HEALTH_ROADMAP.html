Health Product Roadmap

Product-level coordination for Health: what is unreliable today, what user value each stream creates, and what the system should become. Todoist remains the execution log for concrete tasks.

Status date: 2026-05-28
North star Health becomes a personal decision layer, not only a metric dashboard.

The product should answer practical daily questions: can I push today, should I recover, is my energy actually depleted, are the signals fresh enough to trust, and did the recommendation match how I felt later?

What we get when this roadmap lands
  • Readiness says fresh, stale, or low-confidence instead of pretending all inputs are equal.
  • EnergyBank is a separate user-facing capacity indicator with calibrated verdicts.
  • Feature candidates only ship when they beat naive baselines on real tenant data.
  • Subjective check-ins become a validation loop, not a premature auto-tuning system.
Gap 1

Data can be accepted but not trusted yet

Raw ingest is safe, but async derived writes still need a clear failure/reconciliation story.

  • User risk: dashboard and recommendations can lag behind reality.
  • Value target: Health knows when derived data is complete.
Gap 2

Readiness lacks a serving contract

Targets and features exist, but freshness, backfill, and source-epoch behavior are not yet productized.

  • User risk: a score looks authoritative when inputs are stale.
  • Value target: readiness includes trust state, not just a number.
Gap 3

EnergyBank is useful but not fully calibrated

It is a separate capacity signal, but v2 verdict thresholds still need distribution evidence.

  • User risk: the label may be too aggressive or too cautious.
  • Value target: energy verdicts match real depletion and recovery patterns.
Gap 4

Feature search can overfit noise

§6.5 is tempting, but without monitoring it can promote clever-looking false signal.

  • User risk: recommendations change for reasons we cannot defend.
  • Value target: every promoted feature beats a simple baseline.
Gap 5

Feedback is sparse

Subjective check-ins are the right outcome layer, but the data is not mature enough yet.

  • User risk: tuning against too few labels bakes in randomness.
  • Value target: recommendations improve against real felt outcomes.
