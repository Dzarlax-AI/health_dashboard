Subjective check-in MVP: where should it live first?

Pick the entry point that should define the first version. The rest can come later, but one surface should own the habit.

Telegram morning prompt
How do you feel today?

A. Telegram-first

Best for habit formation: one tap in the place where morning reports already arrive. UI dashboard reads the result afterwards.

Dashboard hero widget
Today: readiness 73 · energy 61
Mood · energy · soreness · sickness

B. Dashboard-first

Best for context: you see the score and then add your real-world outcome. Weaker if you do not open the dashboard daily.

One backend, two thin surfaces
Telegram: quick tap
Dashboard: edit / add notes
Storage: one row per tenant/date

C. Hybrid MVP

Best long-term shape, but bigger first PR. Telegram captures the habit; dashboard gives review/edit and makes the data visible.

My recommendation

A for the first slice, designed so C is easy next. Start with Telegram capture + storage + admin/read API. Add dashboard editing once the habit and data shape are proven.
